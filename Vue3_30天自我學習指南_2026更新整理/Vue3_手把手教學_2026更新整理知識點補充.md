# Vue3 手把手教學 2026 更新整理知識點補充

## Day 1：Vue Create App and Mount

### createApp()

#### 1. 知識點是什麼

`createApp()` 是 Vue 3 應用程式的建立入口。它接收一個根元件，通常是 `App.vue`，並回傳一個 app instance。這個 app instance 還沒有畫到瀏覽器上，只是先準備好「這個 Vue 應用要從哪個根元件開始、之後要掛哪些 plugin、要設定哪些全域行為」。

在 Vue 2 常見的是 `new Vue()`；Vue 3 改成 `createApp()`，重點是每個 app instance 都有自己的設定範圍。也就是說，全域元件、plugin、provide、errorHandler 等設定會掛在這個 app 上，不會自然污染到另一個 Vue app。

#### 2. 使用時機

- 專案入口 `src/main.ts` 或 `src/main.js`。
- 建立測試用的小型 Vue app。
- 同一頁上需要掛多個彼此獨立的 Vue app 時。
- 需要在 mount 前註冊 Router、Pinia、全域元件或 plugin 時。

#### 3. 工作中怎麼判斷

看到這段時，可以把它讀成「準備啟動 Vue 應用」：

```ts
import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)
```

此時畫面還不會出現 Vue 內容，因為尚未 `mount()`。如果你要加入 router、Pinia 或其他 plugin，通常會接在這一步後面、`mount()` 前面。

#### 4. 常見錯誤

- 把大量業務邏輯寫進 `main.ts`，導致入口檔變成雜物間。
- 在 `createApp(App)` 後忘記 `mount('#app')`，app 建好了但沒有接到 DOM。
- 在同一個 app instance 上重複 mount。
- 以為 `createApp()` 會自動包含 Router 或 Pinia；其實它們都要用 `app.use()` 額外註冊。

#### 5. 參考來源

- [Vue Application API：createApp()](https://vuejs.org/api/application.html#createapp)
- [Vue Guide：Creating a Vue Application](https://vuejs.org/guide/essentials/application.html)

### mount()

#### 1. 知識點是什麼

`mount()` 是把 Vue app 掛到實際 DOM 容器的動作。常見寫法是 `app.mount('#app')`，意思是找到 `index.html` 裡第一個符合 `#app` 的元素，讓 Vue 從那個容器開始渲染根元件。

它不是「每個元件都呼叫一次」；一般 SPA 專案通常只在入口呼叫一次。之後畫面中的頁面與元件切換，是由 Vue 的元件樹與 Router 管理。

#### 2. 使用時機

- 所有 app 設定完成後的最後一步。
- `app.use(router)`、`app.use(pinia)`、`app.component()`、`app.provide()` 通常都要在 `mount()` 前完成。
- 需要讓 Vue 接管某個既有 HTML 容器時。

#### 3. 工作中怎麼判斷

`index.html`：

```html
<div id="app"></div>
```

`src/main.ts`：

```ts
import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)

app.mount('#app')
```

這兩邊的 selector 必須對得上。若 `index.html` 寫成 `id="root"`，但 `main.ts` 還是 `mount('#app')`，瀏覽器就找不到掛載目標。

#### 4. 常見錯誤

- `#app` 拼錯或 `index.html` 沒有對應容器。
- plugin 放在 `mount()` 之後才 `app.use()`，導致元件初始化時拿不到 router 或 store。
- 把 DOM 查詢、事件綁定、API 呼叫全部塞在 `main.ts`；這些通常應該放進元件、composable、store 或 service。

#### 5. 參考來源

- [Vue Application API：app.mount()](https://vuejs.org/api/application.html#app-mount)

### app.use(router)

#### 1. 知識點是什麼

`app.use(router)` 是把 Vue Router 安裝到 Vue app。安裝後，元件才能使用 `<RouterView>`、`<RouterLink>`、`useRouter()`、`useRoute()` 等路由能力。

Router 本身通常會在 `src/router/index.ts` 建立，`main.ts` 只負責把它裝進 app。

#### 2. 使用時機

- 專案有多頁路徑，例如 `/weather`、`/history`、`/products/:id`。
- 需要用 URL 表示目前畫面狀態。
- 需要 route guard、巢狀路由、動態路由參數。

#### 3. 工作中怎麼判斷

```ts
// src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'
import WeatherView from '@/views/WeatherView.vue'
import HistoryView from '@/views/HistoryView.vue'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/weather', component: WeatherView },
    { path: '/history', component: HistoryView },
  ],
})
```

```ts
// src/main.ts
import { createApp } from 'vue'
import App from './App.vue'
import { router } from './router'

const app = createApp(App)

app.use(router)
app.mount('#app')
```

#### 4. 常見錯誤

- `App.vue` 裡用了 `<RouterView />`，但 `main.ts` 忘記 `app.use(router)`。
- 使用 `createWebHistory()` 部署後，直接重新整理深層路徑會 404；伺服器需要把未知路徑 fallback 到 `index.html`。
- 把 route 設定和頁面業務邏輯混在一起，導致路由檔越來越難讀。

#### 5. 參考來源

- [Vue Router：Getting Started](https://router.vuejs.org/guide/)
- [Vue Router：Different History modes](https://router.vuejs.org/guide/essentials/history-mode)

### app.use(pinia)

#### 1. 知識點是什麼

`app.use(pinia)` 是把 Pinia 安裝到 Vue app。安裝後，元件和 composable 才能正常使用你定義的 store，例如 `useWeatherStore()`。

Pinia 是 Vue 3 常見的全域狀態管理工具，用來放跨頁共用狀態與業務動作。它不是拿來取代元件自己的 local state；只有多個頁面或多個元件都需要共享的資料，才適合放進 store。

#### 2. 使用時機

- 使用者登入資訊、權限、偏好設定。
- 查詢紀錄、購物車、跨頁共用篩選條件。
- API loading、error、data 需要被多個元件讀取。

#### 3. 工作中怎麼判斷

```ts
// src/main.ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const app = createApp(App)
const pinia = createPinia()

app.use(pinia)
app.mount('#app')
```

```ts
// src/stores/weather.ts
import { defineStore } from 'pinia'

export const useWeatherStore = defineStore('weather', {
  state: () => ({
    city: '',
    history: [] as string[],
  }),
  actions: {
    rememberCity(city: string) {
      this.city = city
      this.history.unshift(city)
    },
  },
})
```

#### 4. 常見錯誤

- 在 `app.use(pinia)` 前就於 app 外部直接使用 store，導致 active Pinia 尚未建立。
- 把所有表單輸入都放進 Pinia，讓簡單畫面變得太重。
- 忘記 store 是長時間存在的狀態，離開頁面後資料仍可能保留。

#### 5. 參考來源

- [Pinia：Getting Started](https://pinia.vuejs.org/getting-started.html)

### Vue 3 生命週期

#### 1. 知識點是什麼

Vue 生命週期是「一個元件從建立、掛載到 DOM、因狀態改變而更新、最後被移除」的過程。生命週期 hook 讓你在特定時間點放入副作用，例如讀取 DOM、啟動計時器、註冊事件、清理連線。

在 Vue 3 的 Composition API 中，常見寫法是在 `<script setup>` 裡使用 `onMounted()`、`onUpdated()`、`onUnmounted()` 等函式。

#### 2. 常用 hook

| Hook | 什麼時候發生 | 常見用途 |
| --- | --- | --- |
| `setup()` / `<script setup>` | 元件建立時先執行 | 建立 reactive state、computed、function |
| `onBeforeMount()` | 第一次渲染到 DOM 前 | 少用，通常只需知道此時 DOM 還沒建立 |
| `onMounted()` | 初次 DOM 已建立並插入容器後 | 讀 template ref、接第三方 DOM 套件、啟動 timer |
| `onBeforeUpdate()` | reactive state 造成 DOM 更新前 | 更新前讀取舊 DOM 狀態 |
| `onUpdated()` | DOM 因狀態變更更新後 | 讀更新後 DOM；避免在這裡改 state 造成無限更新 |
| `onBeforeUnmount()` | 元件即將被移除前 | 移除前最後處理 |
| `onUnmounted()` | 元件已被移除後 | 清理 timer、DOM event listener、WebSocket |
| `onErrorCaptured()` | 捕捉子孫元件錯誤時 | 顯示局部錯誤畫面或回報錯誤 |

#### 3. 工作中怎麼判斷

```vue
<script setup lang="ts">
import { onMounted, onUnmounted, ref } from 'vue'

const now = ref(new Date())
let timerId: number | undefined

onMounted(() => {
  timerId = window.setInterval(() => {
    now.value = new Date()
  }, 1000)
})

onUnmounted(() => {
  if (timerId !== undefined) {
    window.clearInterval(timerId)
  }
})
</script>

<template>
  <time>{{ now.toLocaleTimeString() }}</time>
</template>
```

這段可以讀成：元件出現在畫面後開始計時，元件離開畫面後清掉計時器。只要你在 `onMounted()` 裡建立了外部副作用，就要反射性地想「它要不要在 `onUnmounted()` 清掉」。

#### 4. 常見錯誤

- 在 `setup()` 一開始就讀 DOM，結果 DOM 還不存在；需要改用 `onMounted()` 搭配 template ref。
- 在 `onUpdated()` 裡一直修改同一個會觸發更新的 state，造成無限更新。
- `setInterval`、`window.addEventListener`、WebSocket 建了但沒清理，切頁後仍在背景運作。
- 非同步等待後才註冊生命週期 hook；Composition API 的生命週期註冊應該在 setup 階段同步完成。

#### 5. 參考來源

- [Vue Guide：Lifecycle Hooks](https://vuejs.org/guide/essentials/lifecycle.html)
- [Vue API：Composition API Lifecycle Hooks](https://vuejs.org/api/composition-api-lifecycle.html)

## Day 2：Vue SFC Template 和 Render Function

### render function

#### 1. 知識點是什麼

render function 是「用 JavaScript 函式描述畫面」的方式。Vue 的 `<template>` 最後也會被編譯成 render function，所以 template 和 render function 不是兩套完全不同的東西，它們都在描述同一件事：目前狀態應該產生什麼 UI。

大多數業務畫面建議用 template，因為好讀、好維護，也比較容易讓團隊成員一起修改。render function 適合畫面結構非常動態、元件庫需要接收 renderer、或你需要用 JavaScript 組合 VNode 的情境。

#### 2. 使用注意

- 不要把普通頁面為了看起來高階而改成 render function。
- render function 內回傳的是 VNode，不是 HTML 字串。
- render function 的可讀性通常比 template 低，所以要有明確理由才使用。
- 在 Vue 3 裡，如果使用 Options API，可以寫 `render()`；如果用 Composition API，可以在 `setup()` 中回傳一個 render function。

#### 3. 工作上常用知識

- 元件庫常用 render function 做彈性的元件組合，例如 table column、form field、modal content。
- 後台表格若欄位來自設定檔，可能會讓每個欄位提供一個 renderer。
- code review 時，如果看到 render function，要先問「這裡的動態程度是不是 template 或 slot 做不到」。
- debug 時可以把 render function 想成 template 編譯後的手寫版本，重點是確認 props、children、event handler 是否正確傳入。

#### 4. 常見誤解

- 誤以為 render function 比 template 一定更快。實務上 Vue template 編譯器已經能做很多最佳化，手寫 render function 不代表自然更快。
- 誤以為 render function 可以直接回傳 HTML 字串。Vue 期待的是 VNode 或 VNode 陣列。
- 誤以為看不懂 render function 就不能寫 Vue。多數專案每天主要還是寫 template。

#### 5. 小範例

```ts
import { h } from 'vue'

export default {
  props: {
    title: String,
  },
  render() {
    return h('section', { class: 'product-panel' }, [
      h('h2', this.title),
      h('p', '這段內容是由 render function 建立的。'),
    ])
  },
}
```

#### 6. 參考來源

- [Vue Guide：Render Functions and JSX](https://vuejs.org/guide/extras/render-function.html)

### VNode

#### 1. 知識點是什麼

VNode 是 Virtual Node 的縮寫，可以把它想成「Vue 用 JavaScript 物件表示的畫面節點」。瀏覽器真正顯示的是 DOM，但 Vue 在更新畫面前，會先用 VNode 描述畫面應該長什麼樣子，再由 Vue runtime 判斷要怎麼把變更套到真實 DOM。

例如一個 `<div class="box">Hello</div>`，在 Vue 內部可以被表示成一個描述 `div`、props、children 的 VNode。你平常寫 template 時不需要手動建立 VNode，但 render function 與 `h()` 會讓你直接碰到這個層級。

#### 2. 使用注意

- VNode 是描述 UI 的資料，不是實際 DOM element。
- 不要拿 VNode 去呼叫 DOM API，例如 `querySelector()` 或 `appendChild()`。
- VNode children 可以是文字、另一個 VNode、VNode 陣列，或代表 slot 的函式。
- 若畫面沒有照預期更新，要檢查 key、props、children 是否穩定且正確。

#### 3. 工作上常用知識

- 看元件庫原始碼時，常會看到它建立 VNode 再交給 Vue render。
- 動態表格、動態表單、樹狀選單這類元件，有時會以 VNode 組合出不同 UI。
- Vue Devtools 顯示的是元件樹，不等於完整 VNode 樹；VNode 更接近 runtime 內部資料結構。
- 當你在 render function 裡傳錯 children 型態，常會造成畫面不顯示或 slot 沒被執行。

#### 4. 常見誤解

- 誤以為 VNode 就是 DOM。VNode 是輕量描述，DOM 是瀏覽器實際節點。
- 誤以為 Virtual DOM 代表不用管效能。大型列表、不穩定 key、每次 render 都建立大量新物件，仍可能造成效能問題。
- 誤以為一定要懂完整 VNode 內部才能寫 Vue。初學階段只要知道它是 template/render function 和 DOM 中間的描述層即可。

#### 5. 小範例

```ts
import { h } from 'vue'

const vnode = h('button', { type: 'button' }, '儲存')

// vnode 是 Vue 的 UI 描述資料，不是 HTMLButtonElement。
console.log(vnode.type) // 'button'
```

#### 6. 參考來源

- [Vue API：h()](https://vuejs.org/api/render-function.html#h)
- [Vue Guide：Virtual DOM](https://vuejs.org/guide/extras/rendering-mechanism.html#virtual-dom)

### h()

#### 1. 知識點是什麼

`h()` 是 Vue 提供用來建立 VNode 的函式，名字來自 hyperscript。你可以把它讀成「建立一個畫面節點」。它常見的參數是：節點型態、props、children。

節點型態可以是 HTML tag，例如 `'div'`、`'button'`；也可以是 Vue component。props 可以放 class、style、事件、元件 props。children 可以是文字、VNode 陣列，或 slot 函式。

#### 2. 使用注意

- `h()` 通常出現在 render function、JSX 底層轉換、或元件庫內部。
- 事件命名要用 Vue render function 的 props 形式，例如 `onClick`。
- 建立元件 VNode 時，第二個參數是傳給元件的 props。
- 傳 slot 時，children 常會寫成物件，屬性名稱對應 slot 名稱。

#### 3. 工作上常用知識

- 如果你在 table column 設定中看到 `render: row => h(...)`，那通常是在自訂儲存格畫面。
- 寫共用元件時，`h()` 可以把「標籤或元件型態」變成參數，讓元件更彈性。
- debug `h()` 時先看三件事：type 對不對、props 是否傳對、children 是否是 Vue 期待的格式。
- TypeScript 專案可從 `vue` 匯入 `VNode` 型別，描述 renderer 的回傳值。

#### 4. 常見誤解

- 誤以為 `h()` 是 HTML helper。它不是產生 HTML 字串，而是產生 VNode。
- 誤把 DOM event 寫成 `onclick` 字串屬性；在 Vue render function 中通常使用 `onClick`。
- 誤以為 `h()` 只能建立 HTML tag；它也可以建立 Vue component。

#### 5. 小範例

```ts
import { h } from 'vue'
import ProductBadge from './ProductBadge.vue'

export function renderStockBadge(stock: number) {
  return h(ProductBadge, {
    type: stock > 0 ? 'success' : 'danger',
    label: stock > 0 ? '有庫存' : '缺貨',
  })
}
```

#### 6. 參考來源

- [Vue API：h()](https://vuejs.org/api/render-function.html#h)

### slot

#### 1. 知識點是什麼

slot 是 Vue 元件保留給父層填內容的位置。你可以把元件想成一個版型，slot 就是版型中的空格，讓使用端決定要塞什麼內容。

例如 `ProductTable` 負責表格架構，但「操作欄要放編輯按鈕、刪除按鈕、還是詳情連結」常常要由父層決定。這種變化點就很適合用 slot，而不是把所有可能按鈕都寫死在 table 裡。

#### 2. 使用注意

- 預設 slot 用 `<slot />`；具名 slot 用 `<slot name="actions" />`。
- 父層填具名 slot 時，使用 `<template #actions>`。
- slot props 是子元件把資料傳回給父層 slot 內容的方式。
- slot 不是 props 的替代品；props 適合傳資料，slot 適合傳 UI 片段。

#### 3. 工作上常用知識

- 共用表格、卡片、版面、modal、dropdown 很常用 slot。
- slot 可以讓共用元件保持穩定，變化的內容交給使用端。
- 如果元件出現太多 `showEditButton`、`showDeleteButton`、`showMoreLink` 這種開關 props，可能代表該改用 slot。
- render function 中的 slot 通常會以函式形式出現，因為 slot content 需要在正確的渲染時機執行。

#### 4. 常見誤解

- 誤以為 slot 只能放純文字。slot 可以放任何 template 內容，也可以放元件。
- 誤以為 slot props 是父傳子。slot props 的資料方向是子元件提供資料，父層決定怎麼畫。
- 誤以為所有客製都要用 slot。若只是文字、數字或設定值，用 props 會更清楚。

#### 5. 小範例

```vue
<!-- ProductTable.vue -->
<template>
  <table>
    <tr v-for="product in products" :key="product.id">
      <td>{{ product.name }}</td>
      <td>
        <slot name="actions" :product="product" />
      </td>
    </tr>
  </table>
</template>
```

```vue
<!-- ProductListView.vue -->
<template>
  <ProductTable :products="products">
    <template #actions="{ product }">
      <RouterLink :to="`/products/${product.id}/edit`">編輯</RouterLink>
    </template>
  </ProductTable>
</template>
```
